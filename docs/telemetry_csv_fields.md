# Telemetry CSV files: field reference

Generated by the telemetry viewer on 2026-09-23 14:48:38 UTC.

The data comes from Teltonika FMC003 trackers. The server decodes each AVL record the device sends
and appends it as one CSV row. It writes one file per UTC day (`telemetry_YYYY-MM-DD.csv`), filed
under the day of the record's own timestamp, or one file per device connection
(`session_<imei>_<YYYYMMDD_HHMMSS>.csv`). The viewer's **Raw CSV** export uses the same format.
The **Decoded CSV** export expands io_json into named columns. All times are UTC.

## Raw CSV columns

| Column | Type / unit | Description |
|---|---|---|
| received_utc | ISO 8601 UTC | When the server received and stored the record. Can be much later than record_utc because the device buffers records while offline and flushes them later. |
| imei | text | IMEI of the tracker (device identity; one IMEI per vehicle). |
| codec | text | Teltonika protocol the packet used: `Codec8` (1-byte IO ids) or `Codec8E` (2-byte ids plus variable-length values). |
| record_utc | text, UTC | When the device took the reading, human readable (`YYYY-MM-DD HH:MM:SS.mmm UTC`). |
| timestamp_ms | integer, ms | Same moment as record_utc, as Unix epoch milliseconds. Use this for sorting and time maths. |
| priority | integer | Record priority: 0 = low (periodic), 1 = high (event), 2 = panic. |
| latitude | degrees | WGS84 latitude, 7 decimals. 0 together with longitude 0 means no GNSS fix. |
| longitude | degrees | WGS84 longitude, 7 decimals. |
| altitude_m | metres | Altitude above sea level from GNSS. |
| angle_deg | degrees | Heading, 0–359, clockwise from north. |
| satellites | integer | Number of satellites used for the fix (0 = no fix). |
| speed_kmh | km/h | Speed from GNSS. 0 when there is no fix. |
| event_io_id | integer | IO id whose change triggered this record (see the IO table). 0 = periodic record, no triggering event. |
| io_json | JSON object | All IO elements the device sent with this record; see below. |

## io_json

`io_json` is a JSON object with every IO element (sensor reading or status) the device attached
to the record, for example:

```json
{"239":1,"240":1,"21":5,"66":14210,"16":547956,"387":"2b34312e35..."}
```

- **Keys** are IO ids (as strings). Look them up in the table below.
- **Order** is the order the device sent them in (1-, 2-, 4-, 8-byte values, then variable-length).
- **Values** are the raw integers as sent: no unit conversion, and no scaling unless the
  description gives a multiplier (e.g. "×0.1": multiply the raw value by 0.1).
- **Variable-length values** (Codec 8E only) are lowercase hex strings of the raw bytes. For text
  fields such as VIN or ISO 6709, decode the hex as ASCII.
- **Which ids appear** differs from record to record and depends on the device configuration,
  firmware and vehicle (OBD ids only appear when the engine ECU answers). A missing id means
  "not sent", not 0.

## Decoded CSV

Same rows as the Raw CSV, sorted by IMEI and then time. The columns are:

- every Raw CSV column except `io_json`, same meaning as above;
- then one column per IO id seen in the exported selection, sorted by id, with the header
  `Name (id)` (e.g. `Ignition (239)`). A cell is empty when that record did not carry the id.

Accelerometer axes (17/18/19) are already converted to signed values in this export.
